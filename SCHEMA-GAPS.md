# Schema gaps

`schemaVersion` 1 rejects unknown top-level keys. When a bundle needs something `bundle.json` cannot say, record it here and keep the manifest valid.

| Need | What the schema allows | What a bundle would have to do instead |
| --- | --- | --- |
| Pin a plugin to a tag or commit | `plugins` is a git URL or the id of a plugin that is already installed. There is no pin field. | Ship the git URL and document the reviewed commit in the bundle README until the schema can store a pin. `webdev`, `local-ai`, `study`, `gaming`, and `backup` each record the commits they were checked against. |
| A launcher sequence | No field for "open a terminal, then a browser, then another app". `project` only creates folders and an optional script. | Document the sequence in the bundle README. `webdev` describes tmux `tdl`, `https://<name>.localhost`, lazydocker, then the GitHub plugin. `creator` describes the script, then OBS or the screen recorder into `raw/`, then Kdenlive, then `publish.md`. `local-ai` describes a terminal in the project (`ollama run`, `uv run`), then Open WebUI in the browser, then `nvtop`, then the editor on `prompts/` and `evals/`. `study` describes Obsidian on `notes/`, then Zathura on `readings/`, then Typst on `assignments/`, then Anki. `gaming` has no `project`, so it has no launcher sequence. A Quickshell button is later work. |
| A package conflict | `conflicts` is a list of other bundle ids. There is no field for pacman package names that must not be installed together. | Name the packages in the bundle README. `creator` records that Omarchy's `obs-studio` and the AUR package `obs-studio-browser` conflict, and this bundle does not install the browser build. `local-ai` records that `ollama`, `ollama-cuda`, `ollama-rocm`, and `ollama-vulkan` cannot be installed together. `study` records that `zotero-bin` conflicts with the AUR package `zotero`, and this bundle installs `zotero-bin`. |
| A GPU package, or any pick-one group | `packages` is a flat list of names. There is no installer dependency and no pick-one group. | Leave every mutually exclusive package out of `packages`. `local-ai` lists `llama-cpp`, `nvtop`, and `uv`. Ollama stays out. The create script checks `command -v ollama`. When the command is missing, the script explains and offers the Install menu action `install.ai.ollama`. That action selects `ollama-cuda` when `nvidia-smi` is present, `ollama-rocm` when `rocminfo` is present, and `ollama` otherwise, then runs `omarchy-install-app`. The menu branch does not select `ollama-vulkan`. The command name is `omarchy-install-app`. |
| An installer Omarchy already ships | `packages` is official pacman names, installed with `omarchy-pkg-add` and removed with `omarchy-pkg-drop`. `aurPackages` is AUR names, installed with `omarchy-pkg-aur-add` and removed with `omarchy-pkg-aur-drop`. There is no field for an `omarchy-install-*` command, and no way to say "run this installer, which picks packages for the GPU". | Name the menu action in the bundle README and leave its packages out of both lists. `gaming` does this for Steam and Heroic. Install → Gaming → Steam runs `omarchy-install-gaming-steam` (`steam`, then `omarchy-install-gaming-gpu-lib32`). Install → Gaming → Heroic runs `omarchy-install-gaming-heroic` (`heroic-games-launcher-bin`, then the same lib32 step). The lib32 step adds `lib32-vulkan-intel`, `lib32-vulkan-radeon`, `lib32-nvidia-utils`, or `lib32-nvidia-580xx-utils` for the GPUs it finds. |
| A dated project folder | `omarchy bundle project new` takes the folder name as an argument. The manifest cannot compute `<YYYY-MM-DD>-<slug>` from a title. | The create script asks for the title and creates `~/Videos/Projects/<YYYY-MM-DD>-<slug>`. `creator` does this. `project.root` is still `~/Videos/Projects`, and `project.layout` is still the folder list inside that project. |
| A course path from a term and a name | `project.root` is one directory. `omarchy bundle project new` adds a single folder name under it. The manifest cannot compute `<term>/<course>` from two answers. | The create script asks for the term and the course and creates `~/School/<term>/<course>/`. `study` does this. `project.root` is still `~/School`, and `project.layout` is still the folder list inside that course. |
| A user systemd timer | No field for a unit, and install does not run files from the bundle. | Ship the units in a plugin. The person or the agent copies them into `~/.config/systemd/user` after a confirm and enables the timer. `backup` does this from the actions plugin. |
